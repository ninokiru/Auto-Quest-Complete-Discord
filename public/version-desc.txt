## 🎮 Auto Quest Complete Discord

Auto-complete Discord **video, stream and game quests** from one window. Tauri 2 + Rust behind the scenes, Vue 3 on the surface, and no cloud service in between: everything runs on your machine.

## v0.0.5 L2#4 — Discord updates stop breaking the launcher

Everything in L2#1 to L2#3 is still here. This patch is about the three places where a working setup could go dead on its own: a Discord update that moved the client, a cleanup that outlived the quest it belonged to, and a progress poll that kept failing behind a quest that looked alive.

### Changed

- **The saved Discord install finds itself again after an update.** Discord's updater replaces `app-<version>\Discord.exe` while the installation keeps the same identity, so the saved path pointed at a file that no longer existed and the launch stopped with "the selected installation must be relocated" until the client was picked again by hand. The launch now walks the installation root and uses the executable the update left behind, and the client list prefers the freshly scanned path over a saved one that stopped validating. A path you added yourself is never rewritten.

### Fixed

- **A stopped quest's cleanup could break the quest started right after it.** Stopping a quest waits up to 45 seconds; when the wait expired the task was detached while its final cleanup was still running, and that cleanup removes every bridge the app injected. If the next CDP quest had already initialized, the late cleanup took its bridge and the quest died with "Modules not initialized". Cleanups are now counted, and a start waits for the previous one to finish (up to 90 seconds) before it initializes.
- **A CDP play or stream quest no longer sits at 0% forever.** A single failed progress poll was retried on the next tick, but a run of failures left the quest reporting nothing at all until Stop was pressed. Eight failed polls in a row (about two minutes) now end the quest with a clear "progress could not be read" message and its cleanup, instead of pretending it is still watching.

### Checks

- The translation check, the frontend test suite, the runtime identity checks, and the full Rust test suite run on Windows for this release.

**Full Changelog**: https://github.com/ninokiru/Auto-Quest-Complete-Discord/compare/0.0.5-L2.3...0.0.5-L2.4

### How the in-app update works

1. The app compares its own version with the newest release of this repository.
2. Choosing **Update** downloads the `*-setup.exe` asset over HTTPS from GitHub.
3. The download's SHA-256 is compared with the digest GitHub publishes for that asset; a mismatch aborts before anything runs.
4. A small helper waits for this app to quit, runs the installer silently, and starts the installed executable again.

Only Windows is self-updating in this release; other platforms still get the release page link. Downloads are restricted to GitHub hosts.

> [!IMPORTANT]
> If you are still on **L1#3** or **L2#1**, run the `-setup.exe` below once by hand. Those builds restart the old copy after an update, which L2#2 fixed; every in-app update after that install is correct.

### Windows SmartScreen / Defender

These binaries are **not code-signed**. The app rewrites its own process identity and reads locally stored Discord credentials, which is exactly what heuristic scanners flag, so Defender may quarantine the download and SmartScreen may block the first launch. Confirm the file came from this repository, choose **More info → Run anyway**, and add the app folder to Defender's exclusions if it keeps deleting the file.
