## 🎮 Auto Quest Complete Discord

Auto-complete Discord **video, stream and game quests** from one window. Tauri 2 + Rust behind the scenes, Vue 3 on the surface, and no cloud service in between: everything runs on your machine.

## What's New in 0.0.4

This release is about running several accounts at once, and about never losing a quest to a launch that went wrong.

- **Quests on several accounts at the same time.** A quest keeps running for the account that started it, even after you switch. The account menu shows who is signed in, how many quests each one is running, and a **Stop** per quest; switching no longer stops anything. **Add another account** signs a second profile in without disturbing the first, and **Remove** refuses while that account still has work running.
- **Background quests panel.** Quests owned by another account are listed apart from yours, grouped under that account's avatar, with counts taken from the backend registry rather than this page — so a quest you cannot see is never mistaken for one that stopped.
- **Tokens no longer leave the backend.** The local scan now reports profiles only: picking a detected account signs it in by Discord user id, and the page never receives the raw token. The backend type that carries a token has no serialisation at all, so a command that tried to hand one over would not compile.
- **The quest list refreshes itself** every 10 seconds while you are signed in, so newly published quests, claim states and the Orbs balance stop going stale in a window left open.
- **Progress in the right unit.** Activity quests count checkpoints, cloud-game and app quests count seconds — each slot now carries its own unit instead of the interface guessing.
- **Dates and numbers follow the interface language** in the inbox and the update log.
- **A new icon and logo**, drawn from original artwork, regenerated at every window, taskbar and installer size.
- **All 16 interface languages** carry the new strings.

### Stability — client launch and recovery

These are the fixes that stop a quest from dying quietly:

- A CDP launch whose debug endpoint never becomes Discord-ready no longer leaves an untracked client running with `--remote-debugging-port` open. The launcher terminates that instance and reopens your Discord in normal mode before reporting the timeout.
- Restoring a client to normal mode now waits until the app really appears in the process table. A launch that exits immediately is reported as a failure instead of a success with no Discord window on screen.
- Flatpak and snap entries are no longer mistaken for a Vesktop install: their `.desktop` `Exec=` starts with the sandbox manager, which used to be handed Electron's debug flag and never opened a port.
- An install found through a symlink (`/usr/bin/discord`, an `/opt` wrapper) is matched against the running process by canonical path, so Linux and macOS stop launching a second copy of a Discord that is already open.
- Navigating the Discord window is refused while a CDP quest is running — it used to move the window out from under the activity iframe the quest reads its progress from.
- Starting a quest and switching an account are serialized, so a switch that lands while a start is queued can no longer leave the new account posting heartbeats for the account you just left.
- Flatpak and Vesktop sessions report the channel you actually selected instead of always claiming Stable.
- Super properties fall back to Discord `1.0.9262` (client build 641004, Electron 42.11.11) when live extraction fails.

## What's Changed

**Sign-in and accounts**

- `auto_detect_token` returns account profiles instead of tokens, and a new `login_with_account` command signs a detected account in by Discord user id.
- The backend remembers one API client and one credential per account found on the machine; the page addresses them by user id only.
- Account menu with switch / add / remove, plus a panel for quests another account is running. A stop is addressed by the `(account, quest)` pair, so stopping one account's quest can no longer cancel another's copy of the same quest id.

**Quest engine**

- The quest list owns its own refresh timer while signed in, and yields to a running quest's poll instead of racing it.
- Each running slot carries its progress unit, and the progress panel reads the count from the backend's task registry.
- A finished, failed or cancelled task is reported separately from a slot that is still running, so an old record cannot re-announce itself.

**CDP launcher (`discord-cdp-launch-core`)**

- Failed CDP readiness now cleans up the instance it started and restores normal mode, on the official, Vesktop and Flatpak paths.
- Restore waits for the reopened client to be visible; `.desktop` entries are filtered by the program they actually name; symlinked installs compare by canonical path; Flatpak and Vesktop results report the selected channel.

**Interface**

- New application icon and in-app logo from original artwork (all raster sizes, `.ico`, `.icns` and the vector mark regenerated).
- Quest slots ease in and sections slide instead of snapping, and the debug, settings and toast surfaces moved onto theme colour tokens with real dark-mode variants.
- Dates, times and numbers are formatted for the selected interface language.

**Data and checks**

- Super-property fallback build numbers raised to the October 2026 Discord client.
- Two new frontend suites cover account sign-in and account switching; the launcher gained Rust tests for the reopened-client wait, symlinked installs, `.desktop` filtering and unjournaled debug ports.
- 10 new interface strings, translated into all 16 locales.

### How the in-app update works

1. The app compares its own version with the newest release of this repository.
2. Choosing **Update** downloads the `*-setup.exe` asset over HTTPS from GitHub.
3. The download's SHA-256 is compared with the digest GitHub publishes for that asset; a mismatch aborts before anything runs.
4. A small helper waits for this app to quit, runs the installer silently, and starts the new build.

Only Windows is self-updating in this release; other platforms still get the release page link. Downloads are restricted to GitHub hosts.

### Windows SmartScreen / Defender

These binaries are **not code-signed**. The app rewrites its own process identity and reads locally stored Discord credentials, which is exactly what heuristic scanners flag, so Defender may quarantine the download and SmartScreen may block the first launch. Confirm the file came from this repository, choose **More info → Run anyway**, and add the app folder to Defender's exclusions if it keeps deleting the file.
