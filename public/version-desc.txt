## 🎮 Auto Quest Complete Discord

Auto-complete Discord **video, stream and game quests** from one window. Tauri 2 + Rust behind the scenes, Vue 3 on the surface, and no cloud service in between: everything runs on your machine.

## v0.0.5 L3#2 — how much you run at once, how fast it goes, and how you sign in

Second build of the third patch round. Everything here is a dial you can turn: how many quests share one account, how fast video and Activity quests finish, and two new ways to get an account into the window.

### New

- **Quests at once.** Settings → Quest Behavior has a cap you control from **1 to 20**, and it now starts at **3** instead of 20. Every quest past the cap waits in the queue and starts by itself when a slot frees up. Moving the dial above 5 asks first: the warning explains that each extra quest is another presence on one account, and **Accept risk** stays unclickable until a five second countdown finishes. The cap is remembered between runs and travels with a settings preset.
- **Video completion speed up to 10x.** The slider now runs **1.0x to 10.0x in whole steps** and starts at 1.0x. A 10-minute video quest takes 1 minute at 10x. It still has no effect in CDP mode, which drives the real player and stays on Discord's own clock — the panel says so.
- **A break after three fast video quests.** From 5.0x up, the third video quest that *finishes* inside a minute parks video work for **one to two minutes**, chosen at random. Only video quests wait: game, stream and Activity quests keep running, and a queued video starts again on its own when the break ends. Pressing Start on a video card during the break opens the same five-second **Accept risk** dialog, and accepting runs video until that break is over. The progress panel shows the countdown.
- **Activity quests read faster, and you can push them further.** The default checkpoint cadence is halved from 180–300 s to **90–150 s**, so a three-checkpoint quest drops from about 12 minutes to about 6. A new **1.0x–5.0x** dial in the advanced Activity block divides that cadence again — 5x brings it to 18–30 s per checkpoint, with a 15 s floor so progress requests never stack up back to back. The progress bar and its estimate follow the same number, so nothing lies about how far along a quest is.
- **Vesktop is a token source on Windows.** Auto Detect used to read only Discord Stable, PTB and Canary. On Windows it now also reads a Vesktop profile, because that profile carries its own key in its own `Local State` and is decrypted the same way. macOS and Linux are unchanged there: their keys are looked up by a per-client keychain or Secret Service name, and those names are not assumed.
- **Paste many tokens at once.** Under the manual login disclosure, drop a list of tokens — one per line — and press **Add to the list**. Blank and repeated lines are ignored, one bad token never stops the others, each surviving token is verified against Discord first, and the accounts land in the same picker a scan uses. The account you are signed into, and the quests it is running, do not change.
- **A failed scan tells you what it checked.** Instead of one line saying nothing was found, the message now names every client and its state, for example `Discord Stable: not installed; Discord Canary: not installed; Vesktop: signed out, or no token stored`. Only client names and states appear — never a path, never a token, never the text of a decryption error.

### Fixed

- **The pace test states its own cadence.** The Activity pacing test had baked in the old 180–300 s default, so halving it made the bar move twice as far as the assertion expected. The test now pins the interval it measures against, which is what a default change should not be able to break.
- **The settings note no longer contradicts the app.** It claimed local token extraction always uses the official client, and the docs repeated it. Both now say what the scan actually reads, per platform.

### Checks

- rustfmt, clippy, the Rust suite, the frontend suite and the translation parity check all pass on Windows for this release. New coverage: the parallel cap and its persistence, the burst window and the break, the Activity speed dial, batch token import, and the Vesktop profile path.

### How the in-app update works

1. The app compares its own version with the newest release of this repository.
2. Choosing **Update** downloads the `*-setup.exe` asset over HTTPS from GitHub.
3. The download's SHA-256 is compared with the digest GitHub publishes for that asset; a mismatch aborts before anything runs.
4. A small helper waits for this app to quit, runs the installer silently, and starts the installed executable again.

Only Windows is self-updating in this release; other platforms still get the release page link. Downloads are restricted to GitHub hosts.

> [!IMPORTANT]
> If you are still on **L1#3** or **L2#1**, run the `-setup.exe` below once by hand. Those builds restart the old copy after an update, which L2#2 fixed; every in-app update after that install is correct.

### Windows SmartScreen / Defender

These binaries are **not code-signed**. The app rewrites its own process identity and reads locally stored Discord credentials, which is exactly what heuristic scanners flag, so Defender may quarantine the download and SmartScreen may block the first launch. Confirm the file came from this repository, choose **More info → Run anyway**, and add the app folder to Defender's exclusions if it keeps deleting the file.
