## 🎮 Auto Quest Complete Discord

Auto-complete Discord **video, stream and game quests** from one window. Tauri 2 + Rust behind the scenes, Vue 3 on the surface, and no cloud service in between: everything runs on your machine.

## What's New in 0.0.5

This release is about doing more at once, across more accounts, waiting less, and stopping the app from spending work it does not need to.

- **Every other signed-in account's quests, in one list.** Home gained a group per remembered account — its avatar, name and handle above the quests Discord lists for it — so you can farm account after account without signing out and back in. **Run** and **Run all** on those cards carry the account they belong to, and the backend works with that account's own token while the page stays signed in as whoever it was. The 20-quest cap is per account, so a second account's queue does not spend the first one's slots.
- **Quests that need the desktop client are shown, not hidden.** A checkpoint Activity quest or a real Stream can only happen inside the one running Discord, so those cards stay listed with their Run button greyed and the reason printed under it instead of failing when clicked.
- **Four times as many quests at the same time.** The cap per account is now **20**, up from 5. Start them from the queue, watch each one in the progress panel, and stop any single one without touching the rest. The dialogs that used to promise "up to 5" read the real limit from the backend now, so the number you see is the number you get.
- **Up to 36 games simulated at once** in process mode. Each lane owns one game and reports its own phase and countdown, so a reel of games covers a quest that wants hours of play in a fraction of the wall clock. CDP stays single-lane: a spoof is written into the one Discord client, which always clears the previous one first.
- **The game list survives a restart.** Discord's detectable-game catalogue is cached on disk for three days, so the picker and every play-quest start open from disk instead of waiting on two API round trips after each launch or login. Games this machine has run before are offered as **Recently used** chips above the alphabetical list.
- **Sign-in is a step shorter.** The page used to hold its loading state through a SuperProperties sync that the backend had already completed while logging in; that sync now runs in the background, as a retry for a Discord listening on a custom CDP port.
- **A minimized window stops polling.** The 10-second background refresh only runs while the window is visible, and catches the list up the moment you look at it again. Quests are unaffected — they run as Rust tasks, not browser timers.
- **Smaller download.** The Windows installer is compressed with LZMA instead of zlib.

### Little things that add up

- **/** focuses the quest search box, and the key is printed inside the field so the shortcut is discoverable.
- **Ctrl/Cmd+R** refreshes the quest list instead of reloading the window and throwing away a running dashboard.
- The window **reopens on the tab you last used** (Game or Settings). Home stays the landing tab, so signing out still returns there.
- **Find accounts on this device** in the account menu runs the local profile scan and adds every account it validates, without signing the page in or disturbing quests already running.
- Those extra account lists cost one round trip per account, so they refresh on their own 30-second timer, are skipped while the window is hidden, and a refresh that starts mid-read joins the request already in flight instead of doubling the calls.
- The background-quest panel now lists only the tasks no account group already shows, so a running quest never has two Stop buttons.
- The progress bubble shows **x/20** even when a single quest is running, so the new ceiling is visible instead of something you discover by being refused.
- A game with no executable Discord knows about is no longer a dead end: the simulator suggests process names by series and falls back to a CDP spoof.

## Stability — bugs fixed in this release

- **The Settings content column could come up blank.** The section swap was a keyed `<Transition mode="out-in">`, and Vue measures the outgoing node through its root element — the Discord integration panel is fragment-rooted, so leaving it never reported a finished transition and every section after it stayed empty. The swap is now a CSS animation on a re-keyed wrapper, which cannot stall.
- **A game list that never arrived could park the picker forever.** The wait-for-an-in-flight-fetch path polled a flag on a 100 ms timer with no deadline. Callers now await one shared promise, and a second picker opening mid-fetch joins the same request instead of issuing a duplicate call.
- **A progress bar stuck at zero on newer Discord clients.** Some clients hand `userStatus.progress` over as a `Map`, where `Object.values()` comes back empty. The quest scripts now read either shape.
- **A custom process name could escape the simulation folder.** Process names are free text, because the custom-name dialog exists for games Discord has no executable for. A name is now checked to stay inside the simulation directory before it decides where the runner binary lands; a nested name gets its parent directory created instead of being rejected.
- **Interface limits that had moved on but still said 5.** Three confirmation dialogs and the simultaneous-games error were hard-coded; both now interpolate the live cap.
- **A Run button that refused for a reason you could not see.** It now names what holds the simulator — a quest, the idle reel, or a missing executable — instead of looking broken.
- **Another account's quest could be announced as yours.** Quest events carry no quest id and no account id, so a completion or a progress number that arrived while another account was working could end the signed-in account's only slot or overwrite its bar. While another account has a task in flight those bare events are no longer trusted: the backend registry, which records ownership per task, decides whose quest ended — and the notification then names the account and reads the quest name from that account's own list.
- **Two accounts finishing the same quest produced a single notification.** The bell's duplicate check compared the kind and the quest name only, so the second account's ending inside two minutes was silently dropped. The account is now part of that identity, and both the OS notification and the bell entry say which account finished.

### Interface

- The quest list opens with **skeleton rows shaped like the real cards** instead of one spinner in an empty column.
- The idle reel gained a **lane strip**: one row per game currently held, with its phase and the countdown to its handover, and a session total that says it is summed across games.
- The update panel got an on-screen **close** button and its own scroll area; previously the only way out of a long changelog was Escape.
- Sections slide rather than snap, in light and dark, and the animation is dropped for anyone who asks the OS for reduced motion.

### Languages

The interface is now **English and Vietnamese** only. The other fourteen locale files are gone: they were machine-translation drafts nobody reviewed, and every new string had to be paid for sixteen times before a single user read it. The language setting offers the two that remain.

### Checks

- Frontend suites cover the new behaviour: the parallel cap is asserted through the constant rather than a literal, lane counts are pinned for both simulation modes, a saved lane count out of range is dropped, an account switch keeps the game catalogue, and a hidden window skips its refreshes and catches up on reveal.
- A new cross-account suite pins the parts that are easy to get wrong: concurrent reads share one request, a list arriving after an account switch is discarded, each starting mode forwards the account id, a foreign run opens no local progress slot, and a desktop-only quest type is refused before any API call. It also covers the attribution fix: starting or stopping a foreign quest reads the registry at once, an ending reported there carries the account and the listed quest name, and while another account works a bare completion or progress number no longer touches this account's only slot.
- The Rust side gained tests for executable names that try to leave the simulation directory, on both Unix and Windows path shapes, and for which account a quest command runs for — the one the page is on when none is named, the one a command names, and the client-only quests that belong to the signed-in account alone.
- The release workflow now opens its draft release before any build runner boots and uploads each platform's finished bundles straight onto it, replacing a second job that re-downloaded and re-packed everything. Caching moved to `swatinem/rust-cache`, with the bundler's own tool directory cached beside it so a dropped NSIS download cannot throw away a compile that already finished.

## What's Changed

**Concurrency**

- `MAX_PARALLEL_QUESTS` 5 → 20, and `MAX_PARALLEL_SIMULATED_GAMES` / `MAX_CONCURRENT_GAMES` 5 → 36, in Rust and mirrored in the stores.
- The idle session runs one worker per lane, each with its own cancel receiver, so one Stop wakes all of them; lane records are drained and cleaned up before a session is declared stopped.

**Performance**

- Game catalogue cached in `localStorage` behind a shape check, with a three-day freshness window.
- Game, Settings and Debug tabs are lazy-loaded components; only Home ships in the first chunk.
- Idle refreshes are skipped while the window is hidden.
- NSIS `compression` set to `lzma`.

**Sign-in and accounts**

- `scanKnownAccounts()` drives the local profile scan from the account menu; the backend keeps every account it validates, and the active session and its quests are untouched.
- Sign-in no longer awaits a SuperProperties sync the backend already performed.

**Multi-account**

- `get_quests_for_accounts()` reads `/quests/@me` for every remembered account except the one already on screen, with the reads running together instead of one after another. A group carries that account's summary, its quests and, if the read failed, the reason — so an expired token empties one group rather than the whole panel.
- `account_id` became an optional argument on the quest start, accept and claim commands, resolved to the account the page is signed into when omitted. A named account is served by its own stored client, while an exclusive CDP spoof is refused for anyone but the signed-in account.
- `AccountQuestGroupsPanel.vue` draws one section per account with its avatar, name and handle, per-row actions, and a **Run all** that enrolls before starting and stops at the account's own quest cap.
- `QuestCard` gained a `foreign` mode: the card reads progress from the quest payload it was given instead of a local running slot, so two accounts running the same quest id cannot mix up each other's numbers.

**Quest engine and simulation**

- Executable suggestions by game series, a raised simulation coverage ceiling, and a CDP route for games with no executable entry.
- Simulated executable paths are confined to the simulation directory, with nested directories created for a namespaced name.
- Quest progress reads tolerate a `Map` payload.

**Interface**

- Settings section swap rewritten as a re-keyed wrapper with a CSS animation.
- Skeleton list, `/` search hint, lane strip, always-visible running count, block reasons on the Run button, and the update dialog's close button.

### How the in-app update works

1. The app compares its own version with the newest release of this repository.
2. Choosing **Update** downloads the `*-setup.exe` asset over HTTPS from GitHub.
3. The download's SHA-256 is compared with the digest GitHub publishes for that asset; a mismatch aborts before anything runs.
4. A small helper waits for this app to quit, runs the installer silently, and starts the new build.

Only Windows is self-updating in this release; other platforms still get the release page link. Downloads are restricted to GitHub hosts.

### Windows SmartScreen / Defender

These binaries are **not code-signed**. The app rewrites its own process identity and reads locally stored Discord credentials, which is exactly what heuristic scanners flag, so Defender may quarantine the download and SmartScreen may block the first launch. Confirm the file came from this repository, choose **More info → Run anyway**, and add the app folder to Defender's exclusions if it keeps deleting the file.
