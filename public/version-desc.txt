## 🎮 Auto Quest Complete Discord

Auto-complete Discord **video, stream and game quests** from one window. Tauri 2 + Rust behind the scenes, Vue 3 on the surface, and no cloud service in between: everything runs on your machine.

## v0.0.5 L3#3 — the last second stops lying, and one account does its own work

Third build of the third patch round. Two corrections: a video quest that reaches the end of its video now finishes instead of dying on a rounding error, and an account no longer runs quests it cannot see or stop.

### Fixed

- **Video quests no longer die on the last second.** The progress payload is rounded to whole seconds, so a step that landed near the end of the video could be posted as one second *past* it, and Discord answers that with a bare `400` that ended a run that had just finished. The submitted timestamp now stays under the video's length until the final submission, which carries the exact target.
- **A rejected final second says what to do.** When Discord still answers the final submission with `400 {"code": 0}`, the quest stops with a message naming the two real causes — an expired enrollment, or client properties stale for your Discord build — and points at **Settings → Discord Integration → re-sync client info**, instead of three blind retries and a raw error body.

### Changed

- **Cross-account quest farming is gone.** Running another account's quests from this page meant reading every account's list with its own token and starting work the page could then neither see nor stop. The account quest panel and its Run/Accept/Claim/Stop paths are removed; each account's quests are run from that account.
- **Account switching waits for running quests.** A quest has to reach its end, or be stopped, before the account changes. The account menu explains the rule and offers **Stop all quests**.

### Checks

- rustfmt, clippy, the Rust suite, the frontend suite and the translation parity check run in CI for this build.

**Full Changelog**: https://github.com/ninokiru/Auto-Quest-Complete-Discord/compare/0.0.5-L3.2...0.0.5-L3.3

### How the in-app update works

1. The app compares its own version with the newest release of this repository.
2. Choosing **Update** downloads the `*-setup.exe` asset over HTTPS from GitHub.
3. The download's SHA-256 is compared with the digest GitHub publishes for that asset; a mismatch aborts before anything runs.
4. A small helper waits for this app to quit, runs the installer silently, and starts the installed executable again.

Only Windows is self-updating in this release; other platforms still get the release page link. Downloads are restricted to GitHub hosts.

> [!IMPORTANT]
> If you are still on **L1#3** or **L2#1**, run the `-setup.exe` below once by hand. Those builds restart the old copy after an update, which L2#2 fixed; every in-app update after that install is correct.

### Windows SmartScreen / Defender

These binaries are **not code-signed**. The app rewrites its own process identity and reads locally stored Discord credentials, which is exactly what heuristic scanners flag, so Defender may quarantine the download and SmartScreen may block the first launch. Confirm the file came from this repository, choose **More info → Run anyway**, and add the app folder to Defender's exclusions if it keeps deleting the file.
