## 🎮 Auto Quest Complete Discord

Auto-complete Discord **video, stream and game quests** from one window. Tauri 2 + Rust behind the scenes, Vue 3 on the surface, and no cloud service in between: everything runs on your machine.

## v0.0.5 L1#1 — a patch on 0.0.5

This is a small fix release sitting on top of **0.0.5**. Everything that shipped in 0.0.5 (multi-account quest groups, 20 quests per account, up to 36 simulated games, cached game list, the interface pass) is still here; these are the bugs found after it went out.

### Fixed

- **A quest could stop with "Promise was collected" and no explanation.** Long-running CDP evaluations await a promise inside the Discord page. Chromium is allowed to garbage-collect a promise that only the DevTools session is holding, which failed the evaluation even though the page was healthy. An awaited evaluation now parks its promise on a page global for exactly as long as it is pending and drops the slot when it settles, so nothing accumulates and concurrent evaluations on one target (a foreground quest plus its monitor) never share a slot.
- **A quest id was written straight into the injected script.** The video and progress scripts are generated by Rust, and the id used to be interpolated as raw text, so any id containing a quote would have produced broken — or worse, hostile — JavaScript. The id is now serialized as a JSON string literal before it reaches the page, with a Rust test that pins the escaping.
- **Signing out and seeing the login screen could sign you straight back in.** The login screen scans this machine for remembered accounts on entry, which is the point, but a scan that ran right after a deliberate sign-out re-added and re-authenticated the account you just left. One unattended scan is now spent per app run, and logging out spends it, so the account menu still offers **Find accounts on this device** when you want the scan.

### New: patch labels

Small fixes no longer have to wait for the next milestone. A release line can carry numbered patches, written as `0.0.5-L1.1` on GitHub and shown in the app as **v0.0.5 L1#1** — `L1` is the patch build, `#1` the publication attempt. It orders above `0.0.5` and below `0.0.6`, so the in-app updater offers it as an update and then stops offering it once installed. Nothing about the label changes the binary's own version, which stays `0.0.5`.

### Checks

- The video-startup suite follows the escaped quest id, and the Rust side gained tests for promise parking (wrapper shape and the value actually returned over a real DevTools socket) and for the escaping itself.
- A new suite pins the version ordering: numeric cores, release candidates below their stable, patch labels above it, and the `L<n>#<m>` label rendering.

**Full Changelog**: https://github.com/ninokiru/Auto-Quest-Complete-Discord/compare/0.0.5...0.0.5-L1.1

### How the in-app update works

1. The app compares its own version with the newest release of this repository.
2. Choosing **Update** downloads the `*-setup.exe` asset over HTTPS from GitHub.
3. The download's SHA-256 is compared with the digest GitHub publishes for that asset; a mismatch aborts before anything runs.
4. A small helper waits for this app to quit, runs the installer silently, and starts the new build.

Only Windows is self-updating in this release; other platforms still get the release page link. Downloads are restricted to GitHub hosts.

### Windows SmartScreen / Defender

These binaries are **not code-signed**. The app rewrites its own process identity and reads locally stored Discord credentials, which is exactly what heuristic scanners flag, so Defender may quarantine the download and SmartScreen may block the first launch. Confirm the file came from this repository, choose **More info → Run anyway**, and add the app folder to Defender's exclusions if it keeps deleting the file.
