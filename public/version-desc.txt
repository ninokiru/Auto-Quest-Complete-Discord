## 🎮 Auto Quest Complete Discord

Auto-complete Discord **video, stream and game quests** from one window. Tauri 2 + Rust behind the scenes, Vue 3 on the surface, and no cloud service in between: everything runs on your machine.

## v0.0.5 L3#4 — Activity quests count in the right unit

Fourth build of the third patch round. The same three things people reported: identical quests that could not be told apart, identical quests that fought over one Discord client, and an Activity quest that reported failure after Discord had already accepted every checkpoint.

### Fixed

- **Activity quests stopped calling finished work a failure.** The server-side check compared the progress Discord records — a count of *seconds* — against the quest's number of *checkpoints*. Any Activity quest longer than a minute therefore looked rejected, and the run failed with "finished locally, but Discord has not confirmed completion yet" even though Discord had accepted every checkpoint. The comparison is now in seconds, and the failure message says how many seconds Discord actually recorded.

### Changed

- **Identical quests are one card with a count.** Regional variants of one offer share a name, game, expiry and reward but carry different ids, so Home listed them as identical rows and it was impossible to tell which card was which. A still-run group now renders once with a `×N` badge; **Accept** and **Start** act on every variant, and the queue runs them one at a time. Completed or claimed variants keep their own cards so every reward stays claimable.
- **Variants of one quest never run together.** Two group-mates share a single Discord client and a single Activity window, so starting both made them fight over it and fail. A queued variant now waits until its group-mate finishes.
- **Activity checkpoint speed runs to 20x.** The dial now covers **1.0x–20.0x**. The floor between checkpoints drops from 15 s to 5 s so the top of the range is a real cadence — 20x turns the 90–150 s default into 5–8 s — instead of clamping to the same 15 s as 10x.

### Checks

- rustfmt, clippy, the Rust suite, the frontend suite and the translation parity check run in CI for this build.

### How the in-app update works

1. The app compares its own version with the newest release of this repository.
2. Choosing **Update** downloads the `*-setup.exe` asset over HTTPS from GitHub.
3. The download's SHA-256 is compared with the digest GitHub publishes for that asset; a mismatch aborts before anything runs.
4. A small helper waits for this app to quit, runs the installer silently, and starts the installed executable again.

Only Windows is self-updating in this release; other platforms still get the release page link. Downloads are restricted to GitHub hosts.

> [!IMPORTANT]
> If you are still on **L1#3** or **L2#1**, run the `-setup.exe` below once by hand. Those builds restart the old copy after an update, which L2#2 fixed; every in-app update after that install is correct.

### Windows SmartScreen / Defender

These binaries are **not code-signed**. The app rewrites its own process identity and reads locally stored Discord credentials, which is exactly what heuristic scanners flag, so Defender may quarantine the download and SmartScreen may block the first launch. Confirm the file came from this repository, choose **More info → Run anyway**, and add the app folder to Defender's exclusions if it keeps deleting the file.
