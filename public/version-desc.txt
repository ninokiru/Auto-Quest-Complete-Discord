## 🎮 Auto Quest Complete Discord

Auto-complete Discord **video, stream and game quests** from one window. Tauri 2 + Rust behind the scenes, Vue 3 on the surface, and no cloud service in between: everything runs on your machine.

## v0.0.5 L2#3 — a second game quest waits, a flaky update retries, a missing game still runs

Everything in L2#1 and L2#2 is still here. This patch takes the dead ends out of the three flows that were most likely to stop a quest: a second game quest, one refused video update, and a game with no executable this machine can run.

### Changed

- **CDP sets itself up once per Discord session.** Starting a quest through the attached client re-scanned Discord's webpack module table on every quest and then installed the same modules again — that scan is the slowest part of the start and it walks thousands of modules. A page that already holds every module the operation needs is now recognised in a single evaluation, so only the first quest after a Discord start pays for the scan, and the install budget grew from two to six seconds so a cold page cannot fail that first quest with a timeout.
- **A game with no runnable executable plays through Discord instead of stopping.** In simulate mode a title whose executable list has nothing this machine can use used to end the start with a dialog asking to switch to CDP. When the attached Discord client is reachable, the quest now goes straight to that path and keeps running; the dialog is left for the case where CDP is not available at all. This is what the CDP fallback was meant to be — one Start, no answer required.

### Fixed

- **A second game quest was refused instead of waiting.** Starting a game quest while another one ran for the same account ended with "One game quest runs at a time per account" and the quest never ran. The queue already defers that case, so a manual Start now joins the queue and starts by itself as soon as the running quest lets go of the slot; a notice says so instead of an error.
- **One refused video-progress update ended the whole watch.** A video quest sent its timestamp every heartbeat and treated any error as fatal — a single blip in Discord's API threw away a quest that may already have been watching for an hour. A refused update is now retried up to three times, three seconds apart, without skipping the step it was on; only a run of three failures still ends the quest, and a Stop still cancels immediately.

### Checks

- The translation check, the frontend test suite, the runtime identity checks, and the full Rust test suite run on Windows for this release.

### How the in-app update works

1. The app compares its own version with the newest release of this repository.
2. Choosing **Update** downloads the `*-setup.exe` asset over HTTPS from GitHub.
3. The download's SHA-256 is compared with the digest GitHub publishes for that asset; a mismatch aborts before anything runs.
4. A small helper waits for this app to quit, runs the installer silently, and starts the installed executable again.

Only Windows is self-updating in this release; other platforms still get the release page link. Downloads are restricted to GitHub hosts.

> [!IMPORTANT]
> If you are still on **L1#3** or **L2#1**, run the `-setup.exe` below once by hand. Those builds restart the old copy after an update, which L2#2 fixed; every in-app update after that install is correct.

### Windows SmartScreen / Defender

These binaries are **not code-signed**. The app rewrites its own process identity and reads locally stored Discord credentials, which is exactly what heuristic scanners flag, so Defender may quarantine the download and SmartScreen may block the first launch. Confirm the file came from this repository, choose **More info → Run anyway**, and add the app folder to Defender's exclusions if it keeps deleting the file.
