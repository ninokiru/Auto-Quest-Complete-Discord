## 🎮 Auto Quest Complete Discord

Auto-complete Discord **video, stream and game quests** from one window. Tauri 2 + Rust behind the scenes, Vue 3 on the surface, and no cloud service in between: everything runs on your machine.

## v0.0.5 L3#1 — several game quests at once, and a catalogue to plan them from

This is the first build of the third patch round. Two things people kept asking for, plus the visual cleanup that makes the numbers readable.

### New

- **Simulation mode now runs several game quests at a time — one per game.** A simulated game publishes the presence of its own title, so quests for *different* games progress together; two quests for the *same* title still wait for each other, because a title has one simulated executable and one play-time record, and the first to finish would tear down the second's. CDP and heartbeat game quests are unchanged and keep sharing up to 20.
- **A Global quests tab.** A read-only catalogue of every live Discord quest, fetched from the public `api.discordquest.com` dataset: search by quest or game name, filter by task type (Watch / Play / Activity / Stream) and reward type (Orbs / Nitro / Role / Item), a mono countdown to each deadline, and **Open in Discord** — which routes through the attached client when CDP is on and otherwise opens the quest page in your browser. It never accepts, starts or claims anything, sends no account data, and does no IP lookup. Results are cached for five minutes, a stalled request gives up after 20 seconds, and a failed refresh keeps the list you already had.
- **The queue finally says why it is waiting.** Four distinct reasons instead of one blanket message: all 20 game slots busy, a cloud-game Activity holding the client, another game quest holding the account, or another quest already running for this same game.
- **State colours and numerals are consistent.** Pending, completed and video/stream now come from three semantic tokens that each have a dark counterpart, so nothing drifts back to the palette defaults; every timer, percentage, count and port is set in a monospaced tabular figure, so a ticking clock no longer shifts the row around it.

### Fixed

- **Run all on another account can fill the game slots.** The account panel still capped each account at one game quest, even though quests started there go through the direct API and share the account up to 20. It now batches against the real limit.
- **Regional duplicates no longer flood the catalogue.** The dataset lists one row per regional variant of the same quest; identical entries collapse to a single row, and are kept apart only when the reward actually differs. The same applies to task badges, where a desktop and a mobile task with one goal used to print twice.

### Checks

- rustfmt, clippy, the Rust suite, the frontend suite and the translation parity check all run on Windows for this release, and the catalogue parser is covered against the shape of the live dataset.

### How the in-app update works

1. The app compares its own version with the newest release of this repository.
2. Choosing **Update** downloads the `*-setup.exe` asset over HTTPS from GitHub.
3. The download's SHA-256 is compared with the digest GitHub publishes for that asset; a mismatch aborts before anything runs.
4. A small helper waits for this app to quit, runs the installer silently, and starts the installed executable again.

Only Windows is self-updating in this release; other platforms still get the release page link. Downloads are restricted to GitHub hosts.

> [!IMPORTANT]
> If you are still on **L1#3** or **L2#1**, run the `-setup.exe` below once by hand. Those builds restart the old copy after an update, which L2#2 fixed; every in-app update after that install is correct.

### Windows SmartScreen / Defender

These binaries are **not code-signed**. The app rewrites its own process identity and reads locally stored Discord credentials, which is exactly what heuristic scanners flag, so Defender may quarantine the download and SmartScreen may block the first launch. Confirm the file came from this repository, choose **More info → Run anyway**, and add the app folder to Defender's exclusions if it keeps deleting the file.
